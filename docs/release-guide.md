# 群晖数据服务 0.3.0

交付目录中的文件：

- `fastapi-0.3.0.tar.gz`：本次更新的 API 镜像（linux/amd64）。
- `postgresql-17.11.tar.gz`、`powersync-1.27.0.tar.gz`：本轮未改，已有镜像无需再次导入。
- `docker-compose.yml`：与本次 API 配套的配置，内嵌六类业务同步规则；含私有凭据，请勿公开。
- `metadata/`：版本、提交、镜像 ID、SHA-256、隔离栈验证与来源凭据。

## 更新已有项目

1. 在 Container Manager 导入 `fastapi-0.3.0.tar.gz`；界面不接受 gzip 后缀时，解压为 tar 再导入。
2. 将本目录 `docker-compose.yml` 替换现有 `/volume1/docker/PostgreSQL` 项目的配置，然后重建项目。
3. 不删除 `data` 目录，不重新生成密码/签名密钥，不更改身份命名空间。API 启动先执行数据库迁移，再提供接口。
4. 预期 postgres、api、powersync 三个服务持续运行；迁移失败查看 api 日志，不反复删除数据重试。
5. `https://cznas.pp.ua:18281/health` 应返回健康；登录后检查同步与待上传数量，健康接口不能代替复制验证。

本次不新增端口：外部 HTTPS 18281 经 DSM 反向代理到 NAS HTTP 18280；PostgreSQL 与 PowerSync 仅在容器网络中通信。
现有 NAS CPU 配额兼容设置保持不变。本地验证使用隔离数据库和严格 TLS DSM 替身，没有操作真实 NAS。

## 客户端迁入与验收

更新折日到 0.12.0 或更高版本，进入设置 → 同步方式。旧云同步账号点击「完成账本迁入」，首次账号选择云同步。
预览六类业务，逐条选择差异版本，确认「导入并启用个人账本」；工资同月和同一设置只选一个版本。
原试用账本保留相同 ID，试用数据也保留；确认前核对是否需要保留这些记录。原本地账本保留，不双写、不桥接 WebDAV。
每台设备都需完成首次迁入确认。先核对旧设备未迁入修改，再停止用旧客户端编辑；程序无法从未联网设备读取未上传内容。

两台同账号设备验证：六类业务离线编辑 → 重启 → 联网收敛；同时改同条记录 → 选版本；离线删除 → 另一端删除。
再验证不同账号不可见、退出重登保留队列。Android、Windows、Web 分别记录版本、数据与同步状态；本机自动检查不等于三端真实 NAS 验收。
APK 下载更新渠道独立保留。备份、共享账本和管理后台不属于本版本。
