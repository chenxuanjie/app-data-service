## 更新原有 NAS 项目

1. 在 Container Manager 导入 `fastapi-0.4.0.tar.gz`。界面不接受 gzip 时，解压为 tar 再导入。
2. 用配套 `docker-compose.yml` 更新原 `/volume1/docker/PostgreSQL` 项目并重建。
3. 保留 `data` 目录和原有三个服务。API 启动时执行会话表迁移 0007，成功后运行服务；不删除数据重试。
4. 继续使用既有 DSM 反向代理：HTTPS `cznas.pp.ua:18281` → HTTP `127.0.0.1:18280`。
   无需新增容器、公网映射、数据库端口或 WebDAV 端口。静态网页与 `/api/` 已在 API 内同源提供。
5. 访问 `https://cznas.pp.ua:18281/` 打开折日 Web；`/health` 检查服务，不能代替登录与同步验收。
   原 `http://127.0.0.1:8082/` 是独立本地预览，不会随 NAS 部署自动更新，也没有 `/api/`。
6. 安装配套 APK 后，继续使用原服务地址与账号。网页新版本改用 HttpOnly 会话，需要重新登录一次。

网页来源变化会产生不同的浏览器本地存储分区。首次使用新地址前，把原网页中待上传修改同步完；
若原网页仍有未上传数据，先保留原入口处理，不清空浏览器数据。新地址通过同一账号下载服务器记录，
不会直接读取另一个来源的 IndexedDB。原生账号 ID、账本 ID、数据库路径和待上传队列保持不变。

## 文件与更新配置

配套配置的更新根目录为 `/friend/apps/zheri/updates`，由已配置的 WebDAV 共享文件夹 `friend`
及折日发布路径 `apps/zheri/updates` 对应取得，属于 File Station 逻辑路径，不是 `/volume1` 挂载路径。
本轮未修改 NAS 文件或权限；若当前实际清单在别处，仅修改 `APP_DATA_UPDATES_ROOT` 为实际路径。
`APP_DATA_BROWSER_ORIGIN=https://cznas.pp.ua:18281` 必须与网页地址一致。

文件读取沿用当前账号的 DSM 权限；发布工具仍负责把清单与安装包写到原发布目录。
应用内读取已切换账号 API，无需用户另配 WebDAV。没有管理员代读或自动授予权限。

## 验收

1. 网页登录、刷新恢复、关闭重开、退出，再确认不同账号看不到彼此账本。
2. 原生与网页互改六类业务，验证离线保存、重启、删除、冲突和待上传队列。
3. Android 检查更新；有权限账号读到已发布清单，无权限账号显示文件无权限，账号不退出。
4. 对高于已安装构建号的有效 APK 测试下载、取消、重试和系统安装；退出/换账号不能安装旧候选包。
   本地交付没有上传新的清单，因此 NAS 仍显示旧发布版本时，不代表文件 API 失败。
5. 中断服务时仍能使用已有本地数据；恢复后同步和更新分别可重试。

本地验证使用真实 PostgreSQL、PowerSync、SQLite、打包后的 Web，以及严格 TLS DSM 替身。
浏览器协议测试验证 Cookie/CSRF、容器重启和退出撤销；HTTPX 替身不是实际浏览器和真实 NAS 验收。
数据库升级只新增会话表，不改业务表和同步规则。board-game-agent 未修改。
