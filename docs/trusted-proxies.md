# 认证限流与可信代理链

API 只从显式配置的代理读取客户端地址。默认信任列表为空，直接使用 TCP peer；任意请求传入 `X-Forwarded-For`、`X-Real-IP` 或 `Forwarded` 都不能自动获得信任。Uvicorn 继续使用 `--no-proxy-headers`，地址解析由应用中间件单独负责，不改 Host、协议、Origin、Cookie 或 CSRF。

## 每个入口的职责

1. 最外层 HTTPS 反代从真实连接取得客户端地址，覆盖外部传入的转发头。群晖反代是否已这样配置，需要现场核对。
2. 桌游 Web Nginx 仅信任 `BGA_TRUSTED_PROXIES` 列出的上级代理。默认不信任转发头；启用后从右向左排除可信代理，将得到的地址作为单个 `X-Forwarded-For` 发给 API，覆盖原请求头，并清除其他转发协议/主机头。本机 Web 预览同样覆盖转发地址。
3. API 仅在直接 peer 命中 `APP_DATA_TRUSTED_PROXIES` 时解析 `X-Forwarded-For`。从右向左遇到的第一个非可信地址才是客户端；更左侧可伪造的前缀不参与身份判断。重复头、无效地址、超长或超过 16 跳的链不生效；整条链都是可信地址时保留直接 peer。

两个环境变量都为逗号分隔的数字 IP/CIDR，最多 32 项，支持 IPv4/IPv6，拒绝域名、通配符和 `/0`。名单应尽量使用实际代理的单个地址；不要因为地址是内网地址就信任整个内网。

**必须核对每段连接实际可见的 peer。** NAS 的局域网 IP 不一定等于 API 或 Web 容器看到的 peer。Docker 转发可能让多种来源呈现为同一个网桥地址；只有在该入口端口已限制为可信代理可访问时，才可把这种地址列为可信。不能在 API 可被任意来源直连时，凭猜测信任共享 NAT/网桥地址；应先限制入口可达范围，再配置实际代理。这里不自动修改 NAS 防火墙、ACL 或容器网络。

## 配置方式

API Compose 中的 `services.api.environment` 配置 `APP_DATA_TRUSTED_PROXIES`；Web Compose 的 `services.board-game-agent.environment` 配置 `BGA_TRUSTED_PROXIES`。空字符串表示不信任转发头。它们分别描述 API 的上游代理和 Web 的上游代理，值可能不同。

`tools/render_stack.py --trusted-proxy <已核对地址>` 可生成 API 配置，重复参数加入多项。已有私有 Compose 使用 `tools/configure_board_web.py` 的 `--trusted-api-proxy` 和 `--trusted-web-proxy` 生成两份新文件；未指定参数时保留原名单，不推断地址、不替换现有文件或秘密。命令其余参数见 `--help`。需要取消信任时将对应 Compose 环境值改为空字符串，或在工具调用中传入空列表。

示例链仅用于说明：用户 → HTTPS 反代 A → Web B → API。Web 信任实际 peer A；API 信任实际 peer B。原生客户端若经 A 直接访问 API，API 还需信任该路径上实际看到的 A。不要把示例中的代理标识换成未经核对的 NAS 网卡 IP。

重新应用 API/Web 配置并更新对应镜像后才生效。无需数据库迁移，PostgreSQL、PowerSync 和原生客户端无需因此改版；它们继续使用原接口。其他应用的前端反代也要履行相同的转发头覆盖契约，本次不擅自修改其仓库。

## 限流维度

每个 API 进程使用 60 秒窗口：

| 操作 | 键 | 上限 |
| --- | --- | --- |
| 登录 | 应用＋解析后的客户端地址 | 60 次 |
| 登录 | 应用＋账号指纹 | 10 次 |
| 浏览器 bootstrap | 应用＋解析后的客户端地址 | 30 次 |

账号在限流键中去首尾空白并 casefold 后散列，不记录密码或原始账号名。轮换 IP 不能绕过同一应用的账号限额；同一 NAT 下不同账号不再共享原来的 10 次总额。浏览器登录与原生登录复用同一机制，同一应用的旧路由别名不会另开额度。无效 Origin 不消耗 bootstrap 额度。

全局 DSM 并发保持为同一 API 实例跨应用共享的 4 个槽位，等待最多 1 秒；这是独立的服务容量保护，不能按应用复制放大。429 仍使用现有 `rate_limited` 协议，窗口限流附带 `Retry-After: 60`。

每个应用最多保留 1024 个活动计数键；过期清理，不以挤掉有效账号记录来绕过限制。一个应用计数存储满不会清空或占用另一个应用的计数空间。计数是进程内机制，不宣称跨副本共享或重启后保留；未来增加副本时需重新核对整个部署的总预算。

## 验证与现场边界

测试覆盖代理白名单、伪造前缀、重复头、IPv4/IPv6、无效信任配置、跨应用/账号/客户端隔离、窗口恢复、有界计数存储、路由别名以及全局 DSM 并发；真实 PostgreSQL 用于登录和 bootstrap 集成。桌游工程另用已有本机镜像运行真实 Nginx，验证实际入口忽略未信任头、覆盖可信链及拒绝全网信任。

源码和本机验证不代表 NAS 配置已生效。上线仍需记录 API/Web 实际 peer、入口端口可达边界及反代覆盖规则，并以两台客户端和两个应用复验；本次不读取或修改真实账号权限和业务数据。
